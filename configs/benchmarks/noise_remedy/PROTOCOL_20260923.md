# Noise-guarded remedy — locked protocol

Registered while the attribution matrix (`configs/benchmarks/noise_attribution/
PROTOCOL_20260923.md`) was still running and BEFORE any of its partial results
were inspected. The remedy is chosen by the mapping below from the attribution
verdicts, not by comparing remedy scores, so no remedy is selected on test data.

## Mechanism

`ReferenceMatching` gains an opt-in noise guard (`noise_guard: true`). Each
query's Immerkaer noise estimate is divided by the median of the class's support
images; the guard fires when the ratio exceeds k = 9 (fixed earlier from
unlabeled image statistics only). A query that does not fire runs the unchanged
code path, so its prediction is byte-identical to the baseline. Unit tests
(tests/test_noise_guard.py) prove this, and prove that a fired `lowres` /
`deep_only` / `lowres_deep_only` query equals a model configured directly with
that remedy.

## Action selection, fixed in advance from the attribution verdicts

- A2 (resolution) passes, A1 (shallow) does not   -> `lowres` ([448, 672])
- A1 passes, A2 does not                          -> `deep_only`
- A1 and A2 both pass                             -> `lowres_deep_only`
- neither A1 nor A2 passes                        -> `denoise_nlm` (h = 1.0 x sigma)
- A3 (CQ) passing is recorded; a CQ-skip action is not implemented and would be
  a separate follow-up. If A3 is the ONLY pass, implement `no_cq` and run it
  under these same rules.
The other actions may be evaluated on the development condition afterwards as
explicitly labeled post-hoc ablations. They never replace the primary action.

## Conditions

- Development: Gaussian noise severity 3, the stored `MVTecAD_corrupted` root
  (the one behind the published -20.69pp result).
- Held-out, never used for design: shot noise s3, impulse noise s3, speckle noise
  s3, Gaussian noise s1, Gaussian noise s5, generated by
  `scripts/prepare_corrupted_mvtec_seeded.py` (per-image seeds; impulse noise is a
  seeded reimplementation of the library's salt-and-pepper rule because the
  library's own call is not reproducible). Pixel-level digests are recorded.
- Guardrails: MVTec AD clean; brightness, contrast, defocus blur s3 (stored roots);
  MVTec AD 2 `test_public`, all six acquisition strata.
- MVTec AD full 15 classes, 16-shot seed0, frozen DINOv2-L/14, the NA_gated
  configuration plus the guard. Baseline = NA_gated on the same root.

## Pre-registered decision rules

- G1 no-fire: the guard fires on 0 guardrail queries (checked from the same
  pixel statistic the method computes). Any firing is listed, and each affected
  cell must stay within -0.865pp AUPRO of the baseline.
- G2 byte identity: guarded MVTec AD clean metrics equal the NA_gated clean
  metrics exactly, for every class.
- P1 development: guarded - baseline >= +3.0pp AUPRO on Gaussian noise s3.
- P2 held-out: guarded - baseline >= +0.865pp on at least 4 of the 5 held-out
  conditions, and the mean held-out gain >= +3.0pp.
- Reported, not gated: guarded Gaussian-s3 AUPRO against PatchCore 74.0295 and
  SuperAD 71.1048; the guard's firing rate on every condition.

P1 without P2 means the remedy fits the development corruption only and is not
claimed. G1 or G2 failing blocks any claim until explained.

## Scope

Seed 0. The remedy is post-hoc with respect to the Gaussian-noise failure; the
held-out conditions are what support a generalization claim.
