# Outline v10 §3.6 execution protocol — 2026-09-28

All evaluations below use the existing `run.py` pipeline through
`scripts/experiments.py run`, followed by `collect`. Normal support alone is
available to fitting and prediction. Query masks and condition labels are used
only by the evaluator. `test_public` and prior corruption roots are seen
development data; they are not final holdouts. No maps or weights are saved
unless item 6 explicitly requests selected examples.

## Order and common recording

Complete items 1–6 in order. A failed cell is an execution failure, not a score.
Record config, code snapshot, support manifest/content, query and mask
fingerprints, device, logs, metrics, and class scope. Use the canonical
comparison ledger for completed quantitative runs. Reuse the designated dsba3
container and assigned GPU UUIDs; run local work on the existing RTX 4090.

1. **MVTec AD 2 shot × acquisition**: RSG4, published SuperAD (DINOv2-L), and
   PatchCore; shots 1/2/4/8 with nested `VOID_support_{N}.json`, seed 0, full8
   `test_public`. The existing RSG4 runs are the candidate; rerun only missing
   stratum diagnostics or invalid provenance. Comparators retain E11 native
   settings. Primary metric: macro AUPRO@0.05 on `shift_1` (higher is better);
   secondary: pAUROC@0.05 and `shift_1 − regular`. `shift_2/3` use matched
   seven-class regular scopes. Budget: 2 methods × 4 shots × 8 objects = 64
   comparator cells. E10 16-shot anchors have matched support/query/mask hashes,
   but their source checksum differs from this campaign. Rerun their 16-shot
   cells under the current source unless an exact source-impact audit proves
   equivalence (additional budget: 16 comparator cells). Stop this
   item when all required cells and stratum provenance are complete, or report exact
   invalid cells that cannot be safely resumed.
2. **Support-seed replication**: SuperAD and PatchCore at 2/16 shots, seeds
   1–2, using the exact support manifests of the completed RSG4 endpoints.
   Dataset/split/evaluator and main metric as item 1. Budget: 2 × 2 × 2 × 8 =
   64 comparator cells. Compare paired seeds rather than unpaired means.
3. **Fusion identification ablation**: frozen RSG4 bank/feature/evaluator,
   seed-0 16-shot MVTec AD 2 development population. Vary only shallow
   coefficient and threshold operation (fixed weight, hard gate, residual),
   with deep-only as reference; fit q95/q99 from the same normal support.
   Primary AUPRO@0.05, secondary pAUROC/F1-oracle and class/defect-size paired
   contrasts. Locked arms: deep-only; full shallow with coefficients 0.25,
   0.50, and 1.00; hard gate `deep + z5 * 1[z5 > tau99]`; residual
   `deep + relu(z5 - tau99)` (RSG4). Existing same-support 16-shot rows may
   supply the deep-only, full-1.00, and residual anchors after provenance
   audit. Thus the new budget is three arms × eight objects = 24 cells. Do not
   select a coefficient after seeing results. Stop after these arms and audit.
4. **CQ and routing ablation**: matched RSG4 normal support and query. For CQ,
   change only `prediction_postprocess`; for routing compare guard off, always
   lowres, and query guard, with common fusion. Use MVTec AD clean plus the
   predeclared noise roots; report the Gaussian s3 development condition
   separately from held-out noise conditions. Primary AUPRO@0.05; record clean
   cost and firing rate. Reuse valid existing arms after provenance audit.
5. **Cross-dataset/final scope**: MVTec AD and VisA few-shot RSG4 versus
   published methods under paired manifests, seed and evaluator. Existing E9
   RSG3 rows are historical comparators, not automatically RSG4. Report
   development results separately from any genuinely unused final split.
   Do not call a previously inspected population untouched.
6. **Qualitative evidence**: selected query maps and component diagnostics for
   success and failure cases under a declared selection rule. Saving maps is
   enabled only for this bounded set. Record raw/normalized layer scores,
   residual, CQ before/after, noise ratio, selected resolutions, and masks used
   solely for evaluation/visualization.
