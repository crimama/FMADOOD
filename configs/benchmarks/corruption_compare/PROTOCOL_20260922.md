# External-method corruption comparison — locked protocol

## Question and hypothesis

Does RSG3 retain higher anomaly-localization performance than published
few-shot AD comparators when clean normal support is fixed and only the query
distribution is corrupted? Primary metric: mean corrupted AUPRO@0.05 (higher).
Secondary: per-corruption AUPRO, pAUROC@0.05, and clean-to-corruption AUPRO drop
(smaller magnitude). A high shifted score and a small degradation are reported
separately; neither substitutes for the other.

## Fixed comparison

- Dataset: MVTec AD, all 15 classes; development benchmark evidence.
- Conditions: clean, brightness, contrast, defocus blur, Gaussian noise;
  stored ICCV-2023 severity-3 corruption roots.
- Normal support: 16 train/good images, seed 0. The corruption roots contain
  byte-identical clean train/good images; only queries are corrupted. Verify
  support filename identities and content fingerprints across conditions.
- Methods: RegAD, RD4AD, PatchCore, FastRecon, RN-FMLK, SuperAD, and RSG3.
  The six comparator configurations reproduce the existing Table-1 16-shot
  method settings with DINOv2-L. RSG3 uses the already completed matching
  clean/corruption runs; do not rerun it unless provenance validation fails.
- Evaluator: native-map float16 streaming, AUPRO integration limit 0.05;
  inference batch 1. No target adaptation or threshold selection.
- No query labels or masks enter support fitting or prediction. Ground truth is
  evaluator-only. No maps, checkpoints, or fitted weights are saved.
- Seed: 0 only. This is a controlled development comparison, not an untouched
  final evaluation or statistical significance test.

## Budget and execution

Six new comparator methods × five conditions × fifteen classes = **450 logical
class evaluations**. Clean runs use the existing local GPU directly; four
corruption conditions use the four already exposed dsba3 GPUs, one condition
per GPU. Existing containers and allocations only. Timeout 21600 seconds per
class; safe runtime retries remain within the same 450 identities.

## Validity and stopping

Fail collection on missing cells, non-finite/shape-invalid predictions,
condition-dependent support identities/content, or config drift. Runtime failure
is not a scientific loss. Report every completed method/condition without
selecting favorable corruptions. Stop after the declared matrix is complete;
no additional method, corruption severity, shot, or seed sweep is authorized.
